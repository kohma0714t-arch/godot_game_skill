# Game Spec Architect (ゲーム仕様策定オーケストレーター)

ユーザーとの段階的な対話（ヒアリング）を通じて、曖昧なアイデアを洗練されたゲームデザイン・MVP仕様書（GDD）へと落とし込み、後続の専門スキルへパスを渡す親スキルです。

## ワークフローと基本原則

1. **必ずヒアリングを主導する**:
   - いきなり実装に飛び込まず、1問〜2問ずつ段階的に質問を投げかけてユーザーの意図を正確に引き出します。
2. **MVP（最小限のコア体験）にスコープを絞る**:
   - 最初から壮大な機能を作らず、まず「入力して動かし、結果が出る」コアループを明確にします。
3. **成果物を構造化して記録する**:
   - `references/gdd_template.md` に基づき、アーティファクトまたはワークスペース内に仕様書を明示的に記録します。
4. **専門サブエージェントのディスパッチ**:
   - `spec-interviewer`: ヒアリング・対話主導
   - `spec-task-decomposer`: MVPスコープのTODOタスク化
   - `spec-asset-analyzer`: 必要素材の洗い出しと2D/3D判定

---

## 段階的ヒアリング（4ステップ）

### Step 1: ゲームの次元 ＆ ジャンル
- 2Dゲームか、3Dゲームか
- 主要ジャンル（アクション、プラットフォーマー、シューティング、探索、パズル等）

### Step 2: コアメカニクス ＆ 体験
- プレイヤーが一番繰り返すアクション（走る、跳ぶ、撃つ、避ける、集める等）
- 何が達成されると「気持ちいい / 楽しい」か

### Step 3: ルール ＆ クリア/リセット条件
- どうなればステージクリアか（ゴール到達、全アイテム回収、敵全滅等）
- ゲームオーバーやリトライのトリガー（落下、HP0、時間切れ等）

### Step 4: 世界観 ＆ アートの方向性
- 視覚トーン（ローポリ、カジュアル、ダーク、SF、ファンタジー等）
- ※仕様策定後、必ず `game-art-director` スキルへ引き継ぎ、配色やUI規格を固めます。

---

## 後続スキルへのバトンタッチ規則

仕様書が完成・承認されたら、次元判定に基づいて以下の専門スキルを起動・連携します：
- **2Dゲームの場合**: `game-art-director` でUI/トーンを策定後、`godot-2d-specialist` を起動。
- **3Dゲームの場合**: `game-art-director` でトーン策定後、`blender-asset-creator`（3D素材）と `godot-3d-specialist`（エンジン実装）を起動。
